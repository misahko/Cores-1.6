# Custom CPU — RTL на Verilog

Мікрокодоване процесорне ядро власної розробки, натхненне архітектурою **Z80**: 8-бітна шина даних (`DATA_BUS`), 16-бітна шина адреси (`ADDR_BUS`), зовнішня пам'ять підключається через окремий інтерфейс з підтримкою тактів очікування — на кристалі немає вбудованої RAM/ROM. Повна специфікація системи команд — у `ISA.txt`.

## Регістри

8 × 8-бітних регістрів загального призначення `R0–R7`, два з яких мають спеціальну роль:

| Регістр | Роль |
|---|---|
| `R3` (**C**) | результат АЛП / приймач при LOAD, аргумент-джерело при STORE |
| `R4` (**D**) | другий операнд для умовних переходів (`BU`), також джерело даних АЛП у гілці порівняння |
| `R0,R1,R2,R5,R6,R7` | звичайні регістри загального призначення |

Пара регістрів (`ARG0`/`ARG1`) може формуватись у 16-бітну адресу для непрямої адресації пам'яті (`LOAD`/`STORE`/`STOI`) — за аналогією з регістровими парами Z80 (BC/DE/HL).

## Принцип кодування опкоду

Клас інструкції визначається кількома молодшими бітами байта команди, а поле операції та номери регістрів займають старші біти (підтверджено звіркою з `cu.v`: наприклад `MOV` перевіряється як `command[1:0]==2'b00`, `EI`/`DI`/`RETI` — точними 8-бітними значеннями, що збігаються з кодуванням нижче).

| Префікс | Клас | Формат |
|---|---|---|
| `00` | **RF** — переміщення регістр→регістр | `00 [3 R1] [3 R2]` |
| `01` | **ALU** — арифметико-логічні операції | `01 [5 OPCODE] [1 R]`, 2-е слово: `[3 R0] [3 R1] [2 -]` |
| `010` | **BU** — умовні переходи / виклик / повернення | `010 [4 OPCODE] [1 R]` |
| `110` | **SYS** — системні інструкції | `110 [5 OPCODE]` |
| `11` | **BUS** — стек / робота з пам'яттю / immediate | `11 [3 OPCODE] [3 ARG0]` |

## RF — переміщення між регістрами

`MOV` — `R[R2] -> R[R1]`, 1 слово.

## ALU — арифметико-логічні операції (`01 [5 OPCODE] [1 R]`)

Обидва операнди — регістри `R0`/`R1`, обрані у другому слові (`[3 R0][3 R1]`); результат завжди йде в `C` (`R3`).

| Мнемоніка | Opcode | Операція |
|---|---|---|
| AND | `00000` | `C = R0 & R1` |
| NAND | `00001` | `C = ~(R0 & R1)` |
| NOR | `00010` | `C = ~(R0 \| R1)` |
| OR | `00011` | `C = R0 \| R1` |
| XOR | `00100` | `C = R0 ^ R1` |
| XNOR | `00101` | `C = ~(R0 ^ R1)` |
| ADD | `00110` | `C = R0 + R1` |
| SUB | `00111` | `C = R0 - R1` |
| ADC | `01000` | `C = R0 + R1 + CF` (для 16-бітного додавання) |
| SBB | `01001` | `C = R0 - R1 - CF` (для 16-бітного віднімання) |
| SHFL | `01010` | `C = R0 << R1` |
| SHFR | `01011` | `C = R0 >> R1` |
| ROL | `01100` | `C = rotate(R0) << R1` |
| ROR | `01101` | `C = rotatr(R0) >> R1` |
| MIN | `01110` | `C = min(R0, R1)` |
| MAX | `01111` | `C = max(R0, R1)` |
| NOT | `10000` | `C = ~R0` |
| NEG | `10001` | `C = -R0` |
| INC | `10010` | `C = R0 + 1` |
| DEC | `10011` | `C = R0 - 1` |

(20 операцій, точно відповідають `case` у `alu.v`.)

## BU — умовні переходи, виклик і повернення (`010 [4 OPCODE] [1 R]`)

Ціль переходу — 16-бітна адреса з наступних двох слів: `{ROM[PC+1], ROM[PC+2]}`.

| Мнемоніка | Opcode | Умова |
|---|---|---|
| JE | `0000` | `C == D` |
| JNE | `0001` | `C != D` |
| JL | `0010` | `C < D` |
| JLE | `0011` | `C <= D` |
| JG | `0100` | `C > D` |
| JGE | `0101` | `C >= D` |
| CALL | `0110` | зберегти `PC` в стек і перейти |
| RET | `0111` | повернення з підпрограми |
| JZ | `1000` | `C == 0` |
| JNZ | `1001` | `C != 0` |
| JLZ | `1010` | `C < 0` |
| JLEZ | `1011` | `C <= 0` |
| JGZ | `1100` | `C > 0` |
| JGEZ | `1101` | `C >= 0` |
| JMP | `1110` | безумовний перехід |

**Як це реалізовано апаратно:** `bu.v` вміє перевіряти лише 3-бітну умову *відносно нуля* (`num==0`, `!=0`, `<0` тощо, разом 8 варіантів). Для інструкцій, що порівнюють `C` з `D` (`JE…JGE`), керівний автомат (`cu.v`) спершу проганяє `C − D` через АЛП (`aluCommand = SUB`), а вже результат цього віднімання подається на `bu.v` як `num` і перевіряється на знак/нуль тими самими 8 умовами — тобто апаратно `JE`/`JL`/… і `JZ`/`JLZ`/… використовують один і той самий компаратор, різниця лише в тому, що подається на вхід (`C−D` чи сам `C`).

## SYS — системні інструкції (`110 [5 OPCODE]`)

| Мнемоніка | Opcode | Дія |
|---|---|---|
| EI | `00000` | `IME <- 1` |
| DI | `00001` | `IME <- 0` |
| RETI | `00010` | `STACK -> PC`, `IME <- 1` |
| — | `00011` | зарезервовано |
| HALT | `00100` | зупинка |

`EI`/`DI`/`RETI` підтверджено в `cu.v` (точні 8-бітні значення `0x06`, `0x0E`, `0x16` відповідають цьому кодуванню). Явної обробки опкоду `HALT` (`0x26`) в `instructionDecoder` не знайдено — судячи з усього, ще не реалізовано.

## BUS — стек, пам'ять, immediate (`11 [3 OPCODE] [3 ARG0]`)

| Мнемоніка | Opcode | Дія | Розмір |
|---|---|---|---|
| PUSH | `000` | `R[ARG0] -> STACK`, `SP--` | 1 слово |
| POP | `001` | `STACK -> R[ARG0]`, `SP++` | 1 слово |
| MOVI | `010` | `ROM[PC+1] -> R[ARG0]` | 2 слова |
| LOAD | `011` | `addr = {R[ARG1], R[ARG0]}`; `RAM[addr] -> C` | 2 слова |
| STORE | `100` | `addr = {R[ARG1], R[ARG0]}`; `C -> RAM[addr]` | 2 слова |
| LOADA | `101` | `RAM[{ROM[PC+2], ROM[PC+1]}] -> R[ARG0]` | 3 слова |
| STOREA | `110` | `R[ARG0] -> RAM[{ROM[PC+2], ROM[PC+1]}]` | 3 слова |
| STOI | `111` | `ROM[PC+2] -> RAM[{R[ARG1], R[ARG0]}]` | 3 слова |

Для `LOAD`/`STORE`/`STOI` друге слово має формат `[5 -][3 ARG1]` — `ARG1` у старших 3 бітах, 5 молодших бітів наразі зарезервовані/не використовуються.

## Скидання та переривання

- Після `rst`: `PC = 0x0010`, `SP = 0xFFFF`, `IME = 1` (переривання дозволені одразу після старту).
- Таблиця векторів переривань лежить на сторінці 0 (адреси `0x00–0x0F`): 8 векторів (`vec` — 3-бітний), кожен займає 2 байти — тому виконання коду починається з `0x0010`, одразу після таблиці.
- Переривання береться лише на такті `T=0`, коли `IME=1` і CPU не в обробнику (`inIntr=0`); вектор і сам факт запиту фіксуються в `irqLatch`/`vecLatch` до моменту обробки.

## Мікроархітектура

- **Керівний автомат** (`cu.v`) — мікрокодований, керує тактами `T0–T4` (різні інструкції займають від 1 до 5 тактів залежно від кількості слів і звернень до пам'яті). Містить три модулі в одному файлі:
  - `controlUnit` — `PC`, `SP`, регістр команди `IR[0..2]`, прапорець `IME`, головний лічильник `T`;
  - `instructionDecoder` — комбінаційна логіка, що за опкодом і поточним тактом `T` генерує керуючі сигнали (мікрокод системи);
  - `interruptDecoder` — окрема послідовність тактів (`intT`) для обробки переривань.
- **Пам'ять** (`ram.v`, модуль `sram_with_ready`) — параметризована модель зовнішньої пам'яті (`DATA_WIDTH`, `ADDR_WIDTH`, `LATENCY`) з тристейт-шиною даних і сигналом `ready`. Процесор заморожує `T` і `PC`, поки `!memReady && memReq` — імітує мікросхему з ненульовим часом доступу (реальні EEPROM/Flash).

## Карта файлів

| Файл | Призначення |
|---|---|
| `ISA.txt` | специфікація системи команд (формати, опкоди, семантика) |
| `cpu.v` | верхній рівень — з'єднує `controlUnit`, `registersFile`, `alu`, `bu`; тримає latch-регістри `aluAcu`/`aluRes` та обробку переривання |
| `cu.v` | керівний автомат + декодер інструкцій + декодер переривань (3 модулі в одному файлі) |
| `alu.v` | 8-бітне АЛП |
| `bu.v` | блок умовних переходів |
| `rgf.v` | регістровий файл |
| `ram.v` | параметризована модель зовнішньої пам'яті для симуляції (не входить до самого ядра CPU) |

## Інтерфейс `cpu.v` (top-level порти)

| Порт | Напрям | Опис |
|---|---|---|
| `clk`, `rst` | in | тактування та скидання |
| `memReady` | in | готовність зовнішньої пам'яті (wait-state) |
| `irq`, `vec[2:0]` | in | запит переривання й номер вектора |
| `data[7:0]` | inout | тристейт шина даних |
| `addr[15:0]` | out | шина адреси |
| `rw` | out | напрям обміну (1 = запис) |
| `memReq` | out | запит до пам'яті |
